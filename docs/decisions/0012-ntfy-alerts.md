# 0012 – Alerts via ntfy

- **Status:** accepted
- **Context:** an alert must reach a phone wherever it is, not only at home.
- **Decision:**
  - The box sends push notifications to a phone through ntfy (open source), on a private topic generated by `mise run setup`.
  - The messages go through the **public ntfy.sh server**, over the internet. It's free, needs no account, and the box only sends to it, never receives.
  - Every service and timer the box installs alerts when it fails, through one generic unit. A daily check, in the daytime, alerts when a disk is almost full or a unit is still failed.
- **Rejected:**
  - Self-hosting ntfy on the box: the phone would only get alerts on the home network, unless the box were opened to the internet.
  - Email: needs a mail provider, another hosted service, with credentials.
- **Consequences:**
  - The topic name is the only protection: anyone who knows it can read the alerts and send fake ones. The ntfy.sh operators can read them too, so alerts never contain anything sensitive.
  - An alert is sent when the failure happens. If the internet is down at that moment, it is lost, but the daily check reports the unit if it is still failed.
